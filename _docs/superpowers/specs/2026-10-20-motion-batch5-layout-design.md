`dev/js/editorial.js` 在拆包前已有 25 项能力、3785 行；`_docs` 里 2026-09-23 那份体检的 P0/F 系列基本还清

## 2. C1 灯箱多图序列

序列在 `initLightbox` 建立时收集（沿用既有的「≥160px 且未被 `<a>` 包裹」判据），翻页走 `show(n, dir)`：
换 src/alt/caption、更新 `3 / 21` 计数、**只预取相邻两张**（长截图单张几百 KB，打开灯箱那一刻不该把整篇拉下来），
进场用 `translate3d` + 淡入（只动 transform/opacity，与 M 系列同一口径）。

两条不显眼但会咬人的：

1. `dlg` 上原有的 `click → close` 会把「点下一张」一起吃掉，必须放行 `.lightbox-nav`；
2. 触摸翻页要求横向位移 >40px **且** 明显大于纵向（1.5 倍），判错方向的后果是读者竖向一拖就跳页。

实测：点开第 3 张 → 右方向键 `4/21` 类名 `is-from-right` → 左键回 `3/21` `is-from-left` →
两颗钮各命中 44×44 → 从 3 连按左键环回 `21/21` → Esc 关闭。reduce 档滑入类为空、`getAnimations()` 0 条。

## 3. C2 代码块角标与折叠（被体积判据挡过一次）

语言角标 + 「展开全部 N 行」（阈值 12 行）。**外壳复用 `initCodeCopy` 已建的 `.code-wrap`**：
第一版自己套了 `.code-shell`，结果复制钮与「在编辑器打开」被留在新壳外面（实测 `.code-copy` 从外壳里消失），
那是养出第二套抽象。角标也因此从右上改到左上——右上是 `.code-copy` 的地盘。

这一条本批**先做完又被回退过一次**：`check-sw.mjs` 给每页都载的 `editorial.min.js` 定了 17,408B gzip 上限，
加完 C1 后实测 17,419B 越线，而判据注释写着「若再涨，先把命令面板拆成独立延迟加载件，再谈加码」。
抬档位等于绕过它自己写的这句话，所以先回退、拆包（§5），再以 15,324B 的预算接回。

实测：23 个代码块全部有外壳、2 种语言角标、20 个长块可折叠；折叠态 pre 高 374px → 点「展开全部 32 行」
→ 850px、文案变「收起」、`aria-expanded=true`；`.code-copy` 仍在、角标与复制钮不重叠、按钮命中区 44px。

## 4. C3 锚点落点 / C4 读过外显

C3 是纯 CSS：`@keyframes targetFlash` 从 26% `--signal` 底色淡到透明，挂在 `.markdown-body :target` 等三处。
实测 260ms 读到有色中间帧、1.6s 归零；reduce 档时长被全站兜底压到 `1e-05s`。

C4 只做显示不做筛选：筛选要重排整页，与「服务端渲染的信息流 + 纯客户端状态」冲突（刷新前后版面不一致，
抓取读到的又是另一份）；也不划删除线——那是「已处理完」的语义，而回访重读正是这个站想要的。
空书架时直接 return，不无谓改 DOM。首页那条选择器多带一层 `.article-list`：
§4 的 `.post-preview .post-title` 已占三类，同特异度比次序，实测少一层会被压住——标记出现、标题不降色。

实测：种一条足迹后首页 8 张卡里 1 张出「读过」、标题 `rgb(20,22,26)→rgb(105,110,122)`，归档页 5 行同样生效。

## 5. 拆包（C2 的前置）

§4 命令面板 501 行搬进 `dev/js/palette.js`，由 `editorial.js` 的薄桩在首次 ⌘K / 点搜索入口时注入，
骨架清单加一条 `palette.min.js`。`check-sw` 组 2 因此新增「运行时注入件」这一类，
条件是**该地址字符串必须真的出现在某个已构建公共脚本里**——不是白名单免检，桩改错路径就立刻退回孤儿那一支去红。

产物：`editorial.min.js` 17,280B → 15,324B gzip，`palette.min.js` 3.43KB 只在用到时下载。

两处只有真跑浏览器才暴露的错（`node --check` 与三道静态门禁全绿）：
1. 拆分脚本把桩文本存进变量却没插进文件，`initPaletteStub()` 未定义会让每一页整条初始化链抛 ReferenceError；
2. 桩调 `window.BBPalette.open`，而面板的 `open` 是 `initPalette` 的局部函数——外层引用它解析到 `window.open`，
   不报错、不开面板，症状是「第一次 ⌘K 按了没反应」。改为注入完成后**重放同一次交互**。

## 6. D 首屏节奏与遗留

精选从 5 条纵排改 3 条、≥1200 排一行、960–1199 两列、窄屏单列；手机命中区用 `::before` 撑到 44px，
视觉尺寸一像素未动。实测桌面第一篇 `y` 866→717、首屏露出 34px→183px。

**三处遗留，都不是悄悄略过**：

1. **平板/手机首屏仍看不到文章卡**（`y` 1040 / 1014，露出 0px）。窄屏那 1000px 里自我介绍卡占 195px、
   精选占 329px。要首屏见正文就得降级自我介绍，而前置它是 `index.html:67` 注释里写明的既有决策
   （「手机上它决定读者要不要继续往下划」）——推翻一条有理由的记录该本人拍板。
2. **大屏 rail 加宽这条已做又回退，因为收益被自己的实测证伪**。先按「236px 常把目录标题截断」写了改动与注释，
   复测（1240/1440/1599/1600/1920/2560 六档，挑目录最多的一篇 76 条）打脸了：
   `被截断的条目` 在 236px 下就是 **0**，1600 起 rail 确实变 300px、正文恒 760px，但没有任何一处因此变好。
   没有实测收益的版面改动不该留在树里，所以整块回退。正文不拉宽那条判断仍然成立（760px 下中文约 40 字/行）。
3. **C5 分页位置过渡不成立**：分页是服务端链接（`/page2/`…），跨页已由 `@view-transition navigation:auto` 覆盖，
   没有客户端整块替换可治。这条是从设计里划掉的，不是没做完。

## M24 退场基线的验证状态（2026-10-21 结）

`scripts/verify-motion-batch4.mjs` 是本地量具，不在 CI 门禁清单里，而它在这台机器上**读不出可信结果**。
当晚三种形态都遇上了：

- 采样密度自证（门槛 120 帧/300ms）反复退 2：81 帧、75 帧、108 帧——按设计不出数；
- 侥幸过密度的一把（348 帧）报了五条红，其中「书架·落定 末帧仍渲染 op=0.192」是过渡动画**停在半路**
  而不是「没有过渡」；「灯箱·开/偏好面板·开 打开后不是终态 `{op:0, anim:lightboxFade, dur:0.2s}`」
  是入场动画才跑了第一帧就被读走；
- 「⌘K 面板·退场 全程没有中间帧」那一把里采到的 `tr:"none"` **不是** `transition-property`——
  读数量具里 `tr` 取的是 `cs.translate`（`sampleOnce`，第 380 行），淡出层本来就没有 translate，
  这一条不构成「CSS 没生效」的证据，早先把它写成 transitionProperty 是我读错了自己的字段名。

同一份冻结快照、同一批产物，换到**正常渲染的浏览器 + 可信输入**（Playwright `page.keyboard` /
`page.click`，每层先 reload）逐层量，五层全部是「有中间帧、且落到终态」：

| 层 | 开→关的中间取值 | 末态 |
| --- | --- | --- |
| ⌘K 面板 `#cmdk` | 0.771 → 0.569 | `op:0 display:none` |
| 书架 `#shelf-dlg` | 0.773 → 0.570 → 0.406 → 0.283 | `op:0 display:none` |
| 灯箱 `.lightbox` | 0.782 → 0.576 → 0.403 → 0.281 → 0.195 → 0.129 → 0.081 → 0.048 | `op:0 display:none` |
| 偏好面板 `#reader-panel` | 0.636 → 0.363 → 0.192 → 0.094 → 0.039 | `op:0 display:none` |
| TOC 抽屉 `.post-rail`（900×800，滑出） | 21 帧在滑，y 从 252 逐帧走开 | 已离开渲染 |

所以 **M24 的退场行为本身没有被后续改动改坏**，红的全是量具：headless 里过渡与动画的时钟挂在
被提交的帧上，机器一忙，墙钟过了 560ms 而时间轴只走了几帧。

用这个探针时有两个坑值得记着：合成 `KeyboardEvent('Escape')` **关不掉原生 `<dialog>`**
（只有真实按键才触发它的 cancel），所以「书架没关」是探针的锅；而一个 modal `<dialog>` 悬在那儿
会把后续层的打开动作连带污染，逐层验就得逐层 reload。

量具下一步该改的不是门槛，而是**别拿墙钟当状态**：`snap` 之前等到 `document.getAnimations()` 清空
且该层 `opacity≈1`，退场轨迹等到末帧进终态，两处都设上限、超时就报有名有姓的红。
这批改动已在树里（`settleInto`、⌘K/书架窗口放宽到 900ms、0 帧不再 TypeError 崩、
第 2 组入口显式钉 `no-preference`、开层前 `animIdle` 等时间轴），改完当场就见效：
同一份快照、负载仍高（load 6–19），「⌘K 面板·退场」从**全程没有中间帧**变成
**中间帧 14 个 / 共 871 帧，首帧 t=226 op=0.08**，「落定」也过了；「书架」那一格拿到 0 个读数时
报的是有名字的红，而不是旧版的 `TypeError: reading 'rend'`。
再往后一台 CDP 调用直接 30s 不回应（渲染进程被饿死），第 3 组之后没跑到——
**第 3–11 组仍要在真空窗里补一遍**，这不是产物的未知，是这一台机器今晚给不出帧。

**边界画在这里（同日又跑两把）**：负载 10.6 那一把 ⌘K 两格仍过，但「书架」拿到 0 读数、
「灯箱/偏好面板·开」读到 `{op:0, anim:lightboxFade, dur:0.2s}`、`.toc-close` 仍旧落在 y=828——
也就是 `settleInto` 轮询满 4s 之后元素还停在入场位置。这类读数不是等待策略能修的：
过渡的时间轴只在有帧被提交时才前进，而这台机器此刻不给帧。
真要在这样的机器上跑完，下一步是给量具**驱动帧**而不是继续加等待——
`Emulation.setVirtualTimePolicy`（`advance` + 预算）或 `Page.captureScreenshot` 强制提交，
把墙钟换成虚拟时间。这两条会改变其它组的读数口径，得单独设计、单独验，不顺手接进这一版。
