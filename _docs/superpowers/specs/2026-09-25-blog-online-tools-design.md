## 1. 目标与非目标

**目标**

1. 给站内补上一类现在完全没有的内容：可长期使用、可被检索到的开发工具页。
2. 三页都进搜索引擎口径（canonical、JSON-LD、sitemap、llms.txt、内链），而不只是"能打开"。
3. 与站点设计系统零冲突：明暗两主题 × 三档纸张色温全部自动跟随，不新增一个颜色字面量。
4. 每个可算错的地方都有自动化判据，判据本身要能变红。

**非目标（明确不做，避免实现时手滑扩范围）**

- 不做手机号**归属地**：需要 40 万级号段库（MB 级），且公开来源不可靠。只做格式校验 + 运营商识别，页面上写清这一条不做及为什么。
- 不做银行卡**发卡行全量**识别：公开可维护的 BIN 全量表不存在（都是商业库）。Luhn 校验是可靠结论，行别识别基于内置常见行别前缀并标注为参考。
- 不接任何真实身份/企业核验接口，不做姓名与号码一致性查询。核验类接口需企业资质，个人博客无法合规接入。
- 不给工具页做分享卡片：`scripts/og-images.mjs` 目前只覆盖 `_posts`，扩它属于另一件事。工具页的 `og:image` 走站点默认图 `social.og_default_image`，已由 `seoMeta.html` 兜底。
- 不引入前端框架，不改 `vite.config.js` 的 per-entry IIFE 产出方式。

## 2. 调研结论（全部实测，含可复现命令）

### 2.1 站内现状

- `/tools.html` 的语义已被占用：它是「我写的三款 Chrome 插件」产品展示页，数据源 `_data/tools.yml`，导航「工具箱」下拉同源于此。新页面不能叫"工具箱"。
- `site.nav` 是 `sitemap.xml`、`llms.txt`、`index-all.html` 三处的单一数据源；不在 nav 里的页面进不了站点地图，唯一破例是 `index-all.html` 在 `sitemap.xml` 里被点名。**顶级导航现有 7 项 + GitHub + 书架 + 搜索，已经很挤**（`index-all.html` 就是因为"第 9 项会在移动端换行"才不进导航的）。
- 构建链路：`dev/js/*.js`、`dev/sass/*.scss` 各为一个入口，Vite 打成 IIFE 落到 `assets/js|css/<name>.min.*`；两个配置文件都只扫目录一层，**子目录天然不成为入口**（`dev/sass/common/` 已按此约定用着）。CI（`.github/workflows/jekyll.yml`）只跑 `pnpm install --frozen-lockfile` + `pnpm build` + `jekyll build --baseurl`，**没有 lint/format 门禁**。
- `postcss-px-to-viewport` 全站生效，`viewportWidth: 750`，按选择器文本子串命中 `selectorBlackList` 才免换算，`mediaQuery: true`。**这是工具页最大的一个坑**：一个 13px 等宽输入框、240px 侧栏若被换成 vw，1440 屏上会整体放大近一倍，工作台直接不可用。
- `demo/idCardDemo/` 已有一版身份证查询页（详见 §11）。

### 2.2 数据源与算法：已验算，不是照抄

**身份证校验位（18 位）**　权重 `[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`，`Σ mod 11` 查表 `'10X98765432'`。

- `11010119900307355` → 算得 `4`；站内旧库判 `110101199003073554` 有效、`…558` 无效 → **两个独立实现同结论**。（顺带纠正一个流传很广的"示例号"记忆：末位是 4 不是 8。）
- `44052418800101001` → 算得 `4`，`440524188001010014` 在两处都判有效。
- 本写法与 `id-validator` 的 `12 − (Σ mod 11)` 写法在 20 万条随机 body 上 **0 处分歧**。
- 15 位号码：地址码 6 + `yyMMdd` + 顺序码 3，**无校验位**，年份按 `19yy` 解释。**不提供"生成 15 位号码"**（15 位无法表达 20xx 出生，造出来是给人埋坑）；只在出生年落在 1900–1999 时，随 18 位结果附带其等价的 15 位写法并标注"由 18 位去世纪位得来"。

**统一社会信用代码（GB 32100-2015）**　字符集 31 个：`0-9A-Z` 去掉 `I O S Z V`，值按序 0..30；`Wi = 3^(i-1) mod 31` = `1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28`；`C18 = (31 − (Σ Vi·Wi mod 31)) mod 31`，**余数为 0 时校验码取字符 `0`**（约 1/31 的真实码落这一档；写成 `31 − Σ mod 31` 而漏掉外层 `mod 31` 会算出值 31、越界成 `undefined`，是把这段算法从别处抄来时常丢的一步。本轮对过的外部解析资料（极速数据《统一社会信用代码校验码算法》一页）把末位写作 `check_value = (31 − (total mod 31)) mod 31`，与这里同式；31 字符集剔除 `I O S Z V`、`Wi = 3^i mod 31` 两条亦逐项一致。权重表 17 项由本轮幂算式自证，见 §8.1）。

- 标准示例 `91350100M000100Y43`：前 17 位算得校验位 `3` == 样本末位 → **PASS**。
- 同一样本内层的组织机构代码 `M000100Y` + 权重 `[3,7,9,10,5,8,4,2]`，`11 − (Σ mod 11)`（11→`0`、10→`X`）算得 `4` == 样本第 17 位 → **PASS**。两条算法在同一真实样本上互相咬合，说明字符集映射与两套权重表都取对了。
- 结构：`[1 登记管理部门][1 机构类别][6 行政区划][8 主体标识 + 1 组织机构代码校验][1 USCC 校验]`。
- **内层校验值为 10 时写 `X` 还是 `A`，本轮没取到权威口径**（GB 11714 的 `10→X` 与 USCC 附录里按 31 字符集取 `A` 两种说法都流传，取值表原文拿不到）。处理办法是三档而非猜一个：解析侧两种写法都放行（值 10 时接受 `X`/`A`）、第 17 位是其他字母时**不下结论**（非企业主体的第 9–17 位本就不是组织机构代码体系），只有"是数字且与算得的值不等"才判 `false`；生成侧直接回避这一分支（前 7 位固定时，使内层值为 10 的末位在 `0..9` 中至多一个，挪一格即可）。
- 第 1、2 位（登记管理部门、机构类别）的取值含义表同样未取到可核实来源：**模块与面板一律不输出名称，只给字符与其在 31 字符集里的值**（口径见 §5.1 与实现计划 §5.1）。这比"标个『参考』继续显示凭记忆写的名称"更硬——不假装知道，用户也就不会据此填表。

**区划码表：新旧两层，缺一不可**

- 现行源：`modood/Administrative-divisions-of-China` 的 `areas.json`，实测 `HTTP 200 / 228,316B / 2,978 条县级`，结构 `{code, name, cityCode, provinceCode}`，配合 `provinces.json` + `cities.json` 可拼三级全名。
- **这份"现行"表本身有截止日期**：`dist/areas.json` 最后一次提交是 `dc3a1d7acd`（2023-09-13），提交信息写明「数据更新时间：2022-10-31，发布时间：2022-12-29」。也就是说它是 **2022-10-31 口径**，到 2026-09 已滞后约四年。因此：① 生成物与页面必须把 `datasetVersion: '2022-10-31'` 显示出来；② 2022-11 之后新设或改名的区划会落进 §5.4 的"未收录"分支而不是被误报为无效；③ 刷新数据是换 `scripts/fixtures/region-source/` 里的快照，一条命令。
- 站内现有的 `GB2260.js`（npm 包 `id-validator`，MIT，作者 mc-zone；**版本以仓库内的文件头为准 = `IDValidator.js` 标的 v1.2.0**，本节初稿写的"1.3.0"是照着 npm 页面抄来的，站内没有可核证据）共 **3,465 条**（2026-09-25 复算：`Object.keys(require('./demo/idCardDemo/lib/GB2260.js')).length` = 3,465，与冻结快照 `scripts/fixtures/region-source/gb2260-2015.json` 逐字节同集），实测仍含 `110103 北京市崇文区`（2010 撤销）、`110104 宣武区`（2010 撤销）、`110221 昌平县`（2015 改区）、`110228 密云县`（2015 改区）、`371200 山东省莱芜市`（2019 并入济南）——这五条 2026-09-25 逐条从该文件读出，值与左边一致。
- **不写死任何"某码 = 某新设县"的断言。** 起草本节时曾凭记忆写下"源表缺 `653224` 和田地区和安县（2020 设）"，实测两处都错：现行表里 `653224` 是**洛浦县**，而「和安县」「和康县」在这 2,978 条里一条都搜不到——它们 2020 年自和田县析置，但区划代码未见权威公布。这条自身错误正是 §8.1 要求"抽查项必须逐条从源数据读出后再写进判据"的理由。
- 结论不是"换掉旧的"，而是**两层都要**：撤销建制的历史码必须能解出来（真实存在的老号码就带它们），而生成只能从现行表取。
- 反面教材实测：`id-validator` 解 `440524` 得到 `广东省汕头市未知地区` —— 回落到市级后放弃，输出一个"未知地区"。本设计不允许出现这种文案（见 §5.4）。

**三方库评估**

**Web Crypto 口径**：`crypto.subtle.digest` 只在安全上下文可用。站点线上是 GitHub Pages HTTPS，本地 `http://localhost:4000` 属安全上下文 → 都可用；`crypto.subtle` 取不到时（例如有人以 `http://192.168.x.x` 打开）摘要面板显示一行明确提示，不静默出空值。MD5 不在 Web Crypto 内，自带实现（~2.5KB），对 RFC 1321 官方向量校验。

### 4.3 导航高亮判据必须改（现存缺陷）

`_includes/header.html` 现在用 `page.url contains item.url` 判 `is_current`。新页 `page.url` 是 `/tools/idcard.html`，**不包含** `/tools.html`，结果点进工具页后「工具箱」不高亮、下拉的当前项也没有态。

改法：先把 nav 项的 `.html` 剥成目录前缀（`/tools.html` → `/tools`），再用它做前缀匹配。承载当前态的钩子改成 `aria-current` 而不是自造 class，且分两档写（`is-on` 是本节最初的说法，落地时改口，理由见下）：`page.url` 与 nav 项完全相等 → `aria-current="page"`（"这一项就是当前页"）；仅按目录前缀命中（`/tools/idcard.html` 命中 `/tools`）→ `aria-current="true"`（"你现在在这一族里"，而链接目的地并不是你正在看的这页）。第二档不能省：前缀匹配是为在线工具新加的，不区分的话读屏会在工具箱上念"当前页面 /tools.html"，而按下去确实会离开这一页。下拉子项则只有精确匹配一档 `aria-current="page"`（三页工具之间无前缀关系）。样式层按属性选择器出墨条，语义与样式共用同一个事实。改完必须核验：对现有 7 项 × 站内 100+ 页面，`.is-current` 的数量与位置和改前一致，只多出三个工具页应得的高亮（判据见 §8.2）。

### 5.2 `/tools/codec.html` —— 面板式工作区，5 个面板

### 5.3 `/tools/json.html` —— 单工作台，不是面板式

布局：左侧输入（带行号），右侧输出，顶部一条工具栏；视图在「文本 / 树」之间切。树视图支持折叠展开、按 key/值搜索、点击复制 JSON Pointer 路径、**只渲染可视节点、展开时增量渲染**（预算见 §7，用例见 §8.1）。

工具栏：格式化（缩进 2/4/tab 可切）、压缩、校验（错误处标出精确**行列号**并在输入区高亮那一处——原生 `JSON.parse` 的 position 提示过于含糊，这块自实现）、键排序（可选递归/仅顶层）、转义 / 反转义、复制、下载 `.json`、JSON → TypeScript interface（嵌套对象、数组、联合、`null`、可选键都覆盖）、JSON ↔ YAML（js-yaml）、JSON ↔ XML（`DOMParser` + `XMLSerializer`）、JSON ↔ CSV（自实现 RFC 4180：引号转义、内嵌换行、CRLF、BOM、表头行）。

**上面那一句里有三处按事实改了道（2026-09-30 段 4 Task 8 回写，形状以 `dev/js/tools/` 现读的代码为准；回写的目的是别让读 spec 的人以为实现漏了一项，改动都记在段 4 计划 §0.6）**：

- **「在输入区高亮那一处」不是覆盖层高亮，是三件**（复算三条命令，行号会漂所以不写：`grep -n setSelectionRange dev/js/tools/jsonWorkbench.js`、`grep -n 'CTX_WINDOW =' dev/js/tools/jsonWorkbench.js`、`grep -n "const caret" dev/js/tools/jsonView.js`）。落地的三件是 `textarea.setSelectionRange(index, index + len, 'preserve')`（浏览器原生绘制，天然对齐，且用户立刻能复制那一处）+ 结果区一段**三行上下文读条**（病灶行、上一行、下一行，同一行里 `空格 + ^` 指列）+ 那句「第 N 行第 M 列」。两处口径必须分开说清：`第 N 行第 M 列` 数的是**原文**里的那一列（那一个数字才抄得去 `jq`），而插入符落在**窗口**里——读条只取病灶左右各 `CTX_WINDOW` 码元（现读 120），两头切了用 `…` 标明"这里不是行首/行尾"，因为整行进 DOM 会把 5 MiB 上限之内的压缩 JSON 摊成 10 MiB 的串，而三行必须吃同一个窗口否则读条自己换列。为什么不画覆盖层：镜像 `<pre>` 要与 `<textarea>` 的字体度量、换行策略、滚动位置三者任一不匹配就错位，**"错位的高亮"比"没有高亮"更误导**。这一族的判据在 §W（假 DOM 环境断言"选区只动一次"与三行的形状）。
- **JSON ↔ XML 不用 `DOMParser` / `XMLSerializer`**，是本站自定义的**无损子集**（复算：`grep -n "^export const XML_CONVENTION" dev/js/tools/json-convert.js`）。三条理由：① 判据套件跑在纯 Node 22（§8.1 开头那句"纯 Node、无新依赖"），`DOMParser` 在那儿不存在，这一族会变成"只有浏览器测得动"的孤儿；② `XMLSerializer` 不携带类型，`1` 与 `"1"`、`null` 与 `""` 全塌成同一个串，"JSON→XML→JSON 深相等"这条判据不可能过；③ `DOMParser` 对坏输入返回的 `<parsererror>` 文案浏览器各一套，"精确行列号"在它那儿无从断言。落地形状：类型只写在 `t=` 属性上（`obj / arr / str / num / bool / null`，就是 `XML_CONVENTION` 那一句话），对象→每键一元素、数组→`<item>` 子元素、根元素 `<json t="obj|arr">`，同名兄弟元素在读侧归并成数组；写器只发本站读得回来的一集，读器覆盖元素 / 文本 / CDATA / 注释跳过 / 数字与五类预定义实体，**键名非法或出现 DOCTYPE 就整体拒绝并点名**。支持的子集与拒绝项在面板上明写一句。
- **JSON ↔ YAML 的库还是 js-yaml，但内置而非依赖**（§0.4 那条：`dev/libJs/js-yaml.esm.min.mjs`，产物名与版本串复算 `grep -n "^export const YAML_LIB" dev/js/tools/json-convert.js`），并新增一句"歧义值"口径：`yes/no/on/off/null/2024-01-01` 这类串在 YAML 1.1 默认 schema 下会被解成布尔/日期，因此**只承诺 `JSON→YAML→JSON` 往返等价**（写侧带引号）；`YAML→JSON` 方向遇到 `Date` 一律转 ISO 8601 字符串、`!!binary` 转 base64 串、function/undefined **拒**。这句话与 CSV 那句"类型不可逆"（`null` 落空字段、回读一律是字符串，所以 §8.1 那条"三对往返等价"在 CSV 这一对只对"值全为字符串或数字且无 null"的样本断言深相等）都必须渲染进面板——四句说明常量各有判据钉"非空且出现在结果里"（复算：`grep -n "^export const CORE_NOTES\|^export const YAML_NOTES\|^export const CSV_NOTES" dev/js/tools/*.js` 与 `TS_HEADER_NOTE` 那一枚）。


### 5.4 校验输出口径（三页共用，这决定工具可不可信）

- 三态：`有效` / `校验位不符` / `结构非法`。三者必须在 UI 上可区分——"校验位不符"意味着号段结构对但末位不对（最常见是手抄错），"结构非法"意味着长度/字符集/日期本身不成立。
- 逐项判定表：长度、字符集、区划、出生日期、顺序码、校验位，每行给结论 + 依据。**让用户看得见"为什么不行"，而不是只吐一个"不正确"。**
- **区划码查不到时不下"无效"结论**：输出「区划码未收录（可能是已撤销建制或特殊区域码）」，其余项照常判定。真实存在的有效号码确实会带老码和开发区码，判它无效就是工具错。
- 区划回落链（六档，优先级实测自两张表，实现见计划 Task 3 的 `resolveRegion`）：**现行县级 6 位精确命中 → 6 位形如「市级码 + 00」或「省级码 + 0000」按现行市/省级直接命中 → 历史层命中 → 4 位市级回落 → 2 位省级回落 → 落空**。每一档都要在输出里说明命中级别（`level: county|city|province|none`），绝不出现 §2.2 那种「未知地区」。第二条不是修辞：真实号码里 `110100`（市本级）这类码大量存在，若只按"6→4→2 查不到才降一级"实现，它会掉进市级回落、把"这就是市本级"这件事说成"县级查不到"。历史层那一档另有第二个入口：码自己 6 位命中，或它的**前 4 位父市**命中（`371299`——莱芜市 `3712` 已并入济南、现行市级表没有它，旧表里连 `371299` 也没有，只有父码在）。两条给出的结论同型（`abolished` + `level: city` + 市级那半句文案），所以"六档"数是六种结论、不是六个 `if`；第二个入口在 A5 单独立三条断言——把它整档删掉，其余判据一条都不红（实测）。
- **全名拼接不得让同一段地名出现两次**：快照里有 19 条现行县名与所属市名重叠——4 条完全同名（`441900` 东莞市、`442000` 中山市、`460400` 儋州市、`620201` 嘉峪关市），15 条县名自带市名前缀（`130272`「唐山市汉沽管理区」挂在 `1302` 唐山市 下，全是 2022 口径里的功能区）。朴素拼接会得到「广东省东莞市东莞市」「河北省唐山市唐山市汉沽管理区」。规则是**剥掉重复的那一段前缀**，不是给这 19 个码开清单；判据是全表扫描（现行 2,978 + 历史 1,229 条的 `fullName` 一律不得有相邻重复的 ≥2 字面，历史层实测 0 命中）。
- **历史层命中不得断言「已撤销建制」**：初稿的理由（63 条码未变而名称已改，`210112` 东陵区→浑南区、`210782` 北宁市→北镇市、`130502` 桥东区→襄都区 等）落地时实读推翻——那 63 条按县级命中**现行**表，`status` 是 `current`，根本不在历史层里。真正的理由是：历史层那 1,229 条混着四种成因（真撤销 `110103` 崇文区 / 随父级改名 `320801` 淮阴市市辖区 / 旧表口径没有这一档 `110200` 北京市县、`500300` 重庆市(市) / 统计口径 `460037` 海南省西沙群岛），而本站没有码→码的取代关系可给，四种成因一条都断不死。**实测措辞**（`dev/js/tools/region.js` 的 `historicalNote`；A5 用三条断言钉住它——括号必须是现行表截止日、整句不得出现"已撤销"、尾句必须是"可能是"，三条各自实跑过变异确认会红）：`「该区划未见于现行区划表（截止 <现行表截止日>），可能是撤销建制、改码或改名」`，市级历史码把主语换成「所属地市」。括号里给的是**现行表的截止日**（取自产物 `REGION_META.datasetVersion`，决定"查不到"这件事的是它），初稿写的「历史口径 2015」是历史层自己的口径，记在 `SOURCES.json` 与产物头注释里，不塞进给用户看的那句文案。"可能是"不许写成"通常是"：四种成因没做逐条统计。历史层实测 0 条省级形码（A5 断言 `historicalCodes()` 里没有 `xxxx0000`），所以初稿那句"市/省级都补所属地市"里省级那一档不可达，实现只做市级。真撤销的那批由同一句话覆盖，不丢信息。

### 5.5 合规与对外文案口径

- 生成类面板固定一行提示：「随机合成，与真实号码重合的概率可忽略；仅供开发与测试用途，不得用于任何真实身份用途。」`#random` 姓名面板同样声明不指向真实个人。
- 三页全部本地计算：**不发任何网络请求、不写 localStorage 存用户输入**。JSON 页可选"记住上次输入"，**默认关**，开关文案要写清数据只存在本机浏览器。
- `#idcard` 输入框禁用浏览器自动填充与拼写检查（`autocomplete="off"`、`autocorrect="off"`、`spellcheck="false"`），避免测试号被回填进真实表单——这是工具页，不是表单。**同一条口径在段 5 扩到第四页**：`/tools/diff.html` 的两块粘贴框同样带这三件属性，理由换了但形状一样——粘进去的是别人项目的源文件，浏览器不该回填、也不该拿拼写检查去给它画波浪线。

### 5.6 `/tools/diff.html` —— 文件与文本对比（第四页，2026-09-30 段 5 追加）

**这一页与前四节的三处形状不同，先把它们写死，免得"三页"那个词继续自动涵盖它**：

1. **输入成对**。前三页的每一次动作都是"一份输入 → 若干输出"，这一页的输入天生是两栏（A / B），
   所以 §7 的每一道闸门**按侧各判一次**，不是按两侧合计——"每侧 5 MiB"与"合计 5 MiB"是两件事，
   后者会让一侧塞满、另一侧空着时整页不可用。这条口径与 §5.3「超限整体拒绝并说明差多少、不许静默截断」
   同一条红线，差别只在"差多少"要分侧报。
2. **输出是一张对齐的表，不是一段结果文本**。所以前三页那套"结果区整块可复制、复制的是产物正文"
   在这里要拆成两件：复制**差异文本**（unified 那种带 `@@` 的补丁形状）与复制**某一侧的原文**，
   两枚按钮各判各的，不许做成"复制当前看到的"这种一语双关。
3. **不自动跑**。§W 那条「粘贴不自动解析」的判定在这里沿用，理由比 JSON 页更硬：两侧各 5 MiB 时，
   每敲一个键就是两次全量对齐。比较由「比较」按钮与 `Ctrl/Cmd + Enter` 触发，
   输入变化只让"结果已过期"那一格亮起（它是判据，不是提示语——见 §8.1 的 §Z）。
   **（2026-10-01 段 5 Task 9 按落地形状回写这一条，实现一字未改）** 触发只由**按钮**承担，**那一枚键盘捷径没有落地、
   也不该落地**：本框两个粘贴框是 `textarea`，裸 `Enter` 必须是换行；而 `⌘/Ctrl + Enter` 在这里唯一能做的事按钮已经做了，
   加它就要在装配层多接一只 `keydown`、并让"哪些键被这一页吃掉"变成第二份口径。骨架里因此**不写** `.tk-kbd` 那一句
   （`tools-diff.html:106-108` 的块注释记的正是这个决定："写一句不存在的捷径比不写更坏"）。按钮文案是**「重新对比」**
   （`DIFF_ACTIONS` 的 `label` 与骨架 `<button>` 逐字相同，门禁⑤ 比的就是这两处同字）。
   于是本行那句"`Ctrl/Cmd + Enter` 触发"读作**待办未采纳**，其余两句（不自动跑、"结果已过期"那一格是判据）照旧成立——
   判据落点是 `diff/9d`（连发 20 次 `input`：比对一次都没发生、结果区零字节增长）与 §Z 的同名那一判。

**布局**（`layout: workbench` 那一支，与前两页的面板式无关）：上半是两块并排的输入栏，各自带
名称格、`行数 / 字节` 读数、"选文件"按钮与拖放落点；中间一条工具栏；下半是结果区，
视图在「并排 / 行内」之间切，并排档是两栏同一行高对齐、差异行带行内高亮，
行内档是单栏 `-` / `+` / 上下文三态。两种视图都默认**折叠未变行**，每处差异保留上下文 3 行
（`DEFAULT_CONTEXT = 3`），折叠条上写"省略 N 行"并可点开。

**（2026-10-01 段 5 Task 9 按落地形状回写这一段，实现一字未改）** 折叠那一族落地是**四档**不是"固定 3 行"：
上下文那一枚下拉的选项是 `diff / 3 / 5 / all`，值住在 `CONTEXT_VALUE = { diff: 0, 3: 3, 5: 5, all: Infinity }`
（`diffWorkbench.js:87`），默认档是 `DEFAULTS.context = '3'`（`:80`）且与页面骨架里 `<option value="3" selected>`
同字——骨架注释钉的是"第一枚 `<option>` 就是默认档"，否则禁 JS 读到的默认档与启 JS 算出来的那一档会分家。
工具栏里「全部展开 / 上下文三行 / 只看差异」那三枚按钮是这一枚下拉的**快捷键**（`DIFF_ACTIONS` 里那三格各带
`to: 'all' / '3' / 'diff'`），按下走的是"写回那枚 `select` 再 `retune`"，不另存第二份状态（判据 Z21）。
于是上面那句"并可点开"落地的形状是：**点开一条折叠条 = 把那一档调成 `all`，页面上所有折叠条一起归零**，
不是"只展开这一块"——per-block 展开要另存一份"哪几块已展开"的状态，同一次比较就此有了两个口径，而复制与
下载读的那一份是 `unifiedText(result, { a, b, context: CONTEXT_VALUE[s.context] })`，会出现"屏幕上展开三块、
导出的还是折叠的"。复算：`grep -n "CONTEXT_VALUE\|to: 'all'" dev/js/tools/diffWorkbench.js`。

**并排档里缺席那一侧的画法**（原判据 Z4 钉的这一格）：两栏各读同一份行流，某一侧没有对应行时画的是**占位行**——
行在（所以两栏同一行高对齐这件事不靠猜）、类名后缀 `--fill`、**不写** `data-*-ln` 属性、可见行号格留空、正文留空
（`diffView.js:134` 起那一族：`const kind = ln === null ? 'fill' : row.kind;` 与它的三个三元分支）。
它既不是"第 0 行"也不是"一个空行"，读页面的人因此不会以为那一侧少了一行。

**两份输入完全相同时的页面形状**（本段开头那句"折叠未变行"的边界档）：`hunksOf` 在没有 `run` 段时直接返回 `[]`
（`diff-core.js:929`，同一发上还有一条 `total === 0` 的空输入回落 `:926`），所以结果区是**零块、零行、零条折叠条**，
页面上只剩结论那一格——未勾归一化开关时是「两份文本逐字符相同」，勾了且确实有行被归一化时是
「归一化之后两份文本相同（N 行的空白或大小写差别没有计入）」（`diffView.js:218`）。这一档**不画一条"省略 0 行"的
折叠条**，因为它不是"折叠掉了"而是"没有差异可折"；把两者画成同一种形状，就等于用界面说了一句假话。

**三态结论**（这一页的"可不可信"全在这一格）：`完全相同` / `有差异（增 N 行、删 M 行、改 K 处、差异块 P 个）` /
`无法比较`。第三态必须点名是哪一侧坏、坏在第几行第几列（JSON 感知档），或超了哪道闸门、超了多少字节。
"完全相同"与"没跑成功"在 UI 上必须是两种形状——空白结果区加上"两侧一致"与"两侧一致（已忽略空白）"
是三种不同读数，勾了归一化开关时那一句要跟着变。

**行级对齐的口径**（判据 §X）：

- **算法**：公共前后缀行裁剪 + Myers 最短编辑脚本（O(ND)，V 数组按代价线性），
  代价上限 `MAX_COST`。越线**降级**为"中段整块替换"并让 `degraded: true` 上页面——
  这句话写在结果里，因为降级给出的是一份**更长**的编辑脚本，用户有权知道自己看到的是不是最短的。
  不做静默截断，也不做"卡了就少算几行"。
- **归一化只影响判等，不影响展示与行号**：勾了「忽略空白」（首尾去掉、内部连续空白并成一个空格）
  或「忽略大小写」之后，行仍按原文显示、复制走的仍是原文、行号仍是原文行号——只有"这算不算一行改动"
  用归一化后的键。这是这一页最容易做错的一处：做反了会出现"看着一样却报成改动"或反过来。
  §X 里有一条判据专门钉"两侧的 `展示文本` 与 `比较键` 是两个字段"。
- **行尾与末行换行**：CRLF 与 LF 的差别默认**算差异**并显示成 `␍`（勾了忽略空白则并入空白档一起忽略）；
  末行有没有换行符单独报一句「B 的末行缺少换行符」，它是文件对比里最常见的一次真实改动。
- **行内细化**：删除块与插入块按出现顺序逐对配对，对每一对做 token 级对齐，产出 `equal | del | ins` 片段串供两栏各自着色。
  **（2026-10-01 段 5 Task 9 按落地形状回写这一条与它下面那道闸门，实现一字未改）** token 的切分口径是**三条序**、
  两支 `y`（sticky）正则加一层兜底：① 连续空白（含制表）成一枚 `/\s+/y` ② ASCII 词 `/[A-Za-z0-9_]+/y` 成一枚
  （数字段跟着词，所以不另起第三条）③ 其余**逐码点**一枚（`codePointAt`）。本行原写"emoji 与代理对按**码元**算
  token 边界"，落地的是**码点**——一个 emoji 就是一枚 token，`X16` 拿代理对 / ZWJ 序列 / 旗标 / 变体选择符四样形状
  钉"切完不得出现孤立代理项"，按码元切会当场把一枚 emoji 拆成两个各自合法的 surrogate 而那句话根本不该成立。
  带 `y` 从下标往前推而不是每枚 `slice` 一次剩下的整行，是因为闸门允许单行 5 MiB，`slice` 版本在那一行上是 O(n²)。
  每枚 token 同时带 `text`（上色用原文）与 `key`（判等用归一化键），所以行内细化与行级判等共用同一把尺子：勾了
  「忽略大小写」之后行内也不该把 `Foo` 与 `foo` 标成两处改动。复算：`grep -n "WS_TOKEN\|WORD_TOKEN\|codePointAt" dev/js/tools/diff-core.js`。
  **这一族落地的是两道各判各的闸门**，不是一道：
  ① **形状闸门** `MAX_INLINE_TOKENS = 4000` 判的是**单对行两侧 token 数之和**，越线那一对退化成整行着色、
  统计里计一笔 `inlineSkipped`——`tokenize` 因此带一个**单侧** `limit`（一侧最多切到 4,001 枚就收手，
  因为任何一侧单独越线那一和必然也越，"提前收手"不改结论、只避免为一行 5 MiB 的样本建百万项的表）。
  ② **总量预算** `MAX_INLINE_WORK = 3,000,000`，单位是"对齐格子数"（尺度与 `MAX_COST` 同源：每个行对记两笔——
  切分那一刀按 `min(字符数, MAX_INLINE_TOKENS)`、对齐按 `4 × min(裁掉公共前后缀后余下的 token 数, MAX_COST)²`）。
  它存在的理由是形状闸门拦不住的那本账：行内那一步按**行对**逐个跑 Myers，十万行的中文文件逐行改下来，
  光靠单对上限会在行内那一步走掉十几秒。装不下的行对**跳过它继续看下一对**（first-fit，按文档顺序而不是按大小排序，
  所以同一份输入两次结果逐格相同——判据 `X29` 咬跳过不是掐断、`X28` 咬这个确定性），而不是"遇到一对超预算就把后面全掐掉"。
  退化与跳过都要可见，理由同 `degraded`；页面上那句代价说明由 `DIFF_NOTES.inlineSkipped` 给，它同时点名这两道闸门。
- **统计**：`added` / `removed` / `changed` / `unchanged` / `blocks` 五个数。`changed` 是"配对成功、
  两侧都有内容的那一对"，它**不进** `added + removed` 的和里，三者不许在界面上相加当"总差异行数"；
  判据拿的是"五个数各自的算法 + 一条自洽关系（`added ≥ changed`、`removed ≥ changed`）"。
- **差异文本导出**：`--- <A 名>` / `+++ <B 名>` / `@@ -a,b +c,d @@` 那一族，与 `git diff` 的**读法**一致；
  页面上明写"不承诺能被 `git apply` 接住"（上下文行数、`a/` `b/` 前缀、mode 行这些 git 特有口径本站不装），
  这一句是 §5.5 那条"能核实到什么程度就说什么"在本页的落点。

**JSON 感知模式**（判据 §Y，与文本档互斥，切换时结果区整块换形状）：

- 读侧**自带一份**，不 `import` `json-core.js`。这是构建层的硬约束不是审美：`json-core.js` 已被
  `toolJson.js` 那一个入口 reach，diff 入口再 reach 它，Rollup 就把两个入口共用的模块切成带 `import{`
  的共享 chunk，`iife-wrap` 之后整页 SyntaxError 而构建 exit=0（`toolkitCore.js:5-9` 记的正是这个坑，
  判据在门禁④）。两条出路选了便宜的那条：把 `json-core` 挂进 `window.Tk` 会让**已上线四页**各自的
  §7 总量格一起重算；自带一份只涨这一页。
- 既然自带，就要**对拍**：§Y 有一条拿同一批样本同时喂 `json-core` 的解析与本页读侧，要求"合法 / 非法、
  非法时的行与列、解析出的值"三件同结论。先例是 §B 的"与站内旧库对拍"——**两个独立实现同结论才算过**。
- 比较口径：对象按**键名**比（键顺序无关，所以只有顺序不同判"完全相同"，且那句结论要写成
  「仅键顺序不同，按 JSON 值判为相同」）；数组按**索引**比；类型变化（`1` → `"1"`、`{}` → `[]`）
  单列一档 `type`，不与 `change` 混。每格变更给：JSON Pointer（转义规则与 §5.3 树视图那一份
  **逐字符相同**：`~` → `~0`、`/` → `~1`，两份实现由 §Y 对账）、前后值的紧凑串（各限 `PREVIEW_CHARS`，
  切了要带省略号）、归属档（`only-a` / `only-b` / `both`）。
- **数组的"移动"不识别**：把 `x[3]` 挪到 `x[1]` 会报成一串改。页面上明写这一条不做及为什么——
  与 §5.1「不做号码归属地」同一类诚实：没有可靠口径就不下结论，而不是先做了再藏着。

**文件输入**（`FileReader` 是环境量，只能出现在入口注入的 `env` 里，装配层零命中——沿用 §W10 / W11 那条红线）：

- 两路都通：`<input type="file">` 与拖放落点，每侧各一套；文件名进那一侧的名称格并参与差异文本那两行。
- 上限先按 `file.size` 判（**不读进内存再判**），超限拒并说明超了多少字节；读到的内容再按 §7 的
  行数闸门判一次，两道各报各的。
- 非 UTF-8 与二进制：内容里出现 NUL，或解出 `U+FFFD`，就整份拒掉并写「看起来不是 UTF-8 文本」。
  不给"仍然按文本比较"的开关——多一个状态就多一档没人测过的界面，而这一档的产物本来就没人能用。
- 本页**不做**"记住上次输入"：两侧各可达 5 MiB 的东西存进 `localStorage` 不是好主意，页面上把这一条
  与"输入不出本机"一起写明（§5.5 那一句在本页的落点）。

**与 §5.4 那套三态的关系**：本页不套用「有效 / 校验位不符 / 结构非法」，但它沿用 §5.4 的精神——
**每个结论都给依据**。"无法比较"必须点名哪一侧、哪一行、哪一列；"降级"必须说它换成了什么；
"忽略空白后相同"必须带着那句是被忽略的口径，而不是直接报"相同"。

### 6.3 面板框架：渐进增强 + hash 深链 + 真 ARIA

面板全部由 Jekyll 构建期渲染进 HTML（跟 `demo.html` 那次"从 JS 回填改成构建期渲染"的判断一致：禁用 JS 与爬虫都要看得见内容）。`toolIdcard.js` 加载后把它们升级成「左侧粘性索引 + 一次只显示一个面板」的工作区：

- `role="tablist"` / `role="tab"` / `role="tabpanel"`，方向键上下切换、`Home`/`End`、roving `tabindex`（WAI-ARIA Tabs 模式），焦点环复用站点现有 `:focus-visible` 样式。
- `#hash` 与当前面板双向同步，深链进来直接展开对应面板；hash 变化不触发滚动跳动（`scroll-margin-top` 顶开固定头）。
- **两种 hash 形状都认（2026-10-01 修 A 落地）**：索引条那十枚 `<a>` 的 `href` 从裸 `#{{ p.slug }}` 改成
  `#{{ tk.prefix }}-panel-{{ p.slug }}`——只有这一形指的是产物里真实存在的 id，禁 JS 那一档的"退成普通锚点链接"才成立；
  而 `toHash()` 往地址栏写的**仍是裸 slug**，所以 `parseHash` 必须双认。形状是**先剥尾段再查白名单**：
  `stripPanelPrefix()` 用 `s.toLowerCase().lastIndexOf('-panel-')` 找标记（大小写不敏感，与它下面那句查白名单的口径一致），
  认不出标记就整串去认，认得出就只拿最后那一段；`id` 仍是白名单里的字符串或 `null`，**剥头不等于放宽**，未知仍然是未知。
  判据 D4 钉四串认（`#idcard-panel-uscc` / 无 `#` / 全大写 / `bankcard-panel-bankcard` 这种"前缀与 slug 同名"）与四串仍判未知
  （`#idcard-panel-nope` / `#idcard-panel-` / `#idcard-panel-uscc-z` / `#panel-uscc`），并钉"以锚点形状开局仍落到那块面板、
  写回地址栏的仍是裸 slug"。
- JS 未执行时：面板全部可见、按文档顺序排、锚点照常跳，左侧索引退化成普通目录链接。
- 面板内任何一块抛错只塌那一块（每面板独立 `try/catch` + 就地错误条），不整页崩。

### 6.4 视觉、主题与 px→vw 例外（关键约束）

- 全部取 `dev/sass/common/tokens.scss` 的语义变量（`--paper` / `--surface` / `--surface-2` / `--ink` / `--ink-2` / `--ink-3` / `--ink-4` / `--rule` / `--signal` / `--radius-*` / `--dur-*` / `--ease-*`），**不写一个颜色字面量**。暗色（`body.night-mode`）与三档纸张色温（`html[data-rs-paper]`）因此自动跟随，不需要第二份覆盖表——这正是 `tokens.scss` 文件头声明的设计意图。
- 文字对比度只允许用 `--ink` / `--ink-2` / `--ink-3`；`--ink-4` 实测在纸上只有 3.78:1，**不得用于小于 18px 的正文性文字**（`tokens.scss` 注释与项目记忆里都记着这一条，站内 86 个 10.5–13px 消费者是它的上限）。
- **必须进 `selectorBlackList`**：新页类名统一前缀 `.tk-`（toolkit）与 `.jt-`（JSON 工作台），在 `postcss.config.js` 里加这两条，理由与 `.lab-content`/`.cmdk`/`.shelf` 同族——工作台尺寸（行号栏宽、等宽字号、缩进步长、树的折叠三角）按桌面固定值设计，被换成 vw 会在大屏上整体放大、页面不可用。加完必须核验：产物 `assets/css/toolkit.min.css` 里 `.tk-`/`.jt-` 规则中不残留任何 `vw`（`mediaQuery: true` 意味着 `@media` 里的 px 也会被换算，只看一条规则不够）。
- 响应式：索引在 ≤900px 折成横向滚动 chip 条；JSON 工作台 ≤900px 从左右分栏改成上下堆叠 + 视图切换；**必须实测中间断点（901–1100px）**，不只看 375/1440 两端——项目记忆里那条"删了 `nth-child(2n)` 的 float 只有 800–1000px 塌"的教训就是没测中间档。

## 9. Git 与并发会话

仓库现状（开工时实测）：工作区有另一会话 9 处未提交改动（含 `_config.yml`、`README.md`、`USAGE.md`、`_layouts/post.html`、`dev/js/editorial.js`），reflog 显示同一时段它已提交 4 次；`deploy-github.sh` 会 `git add -A`。

规则：

1. 不跑 `deploy-github.sh`，不 `git add -A`/`git add .`；**只按文件名 stage 自己碰的那些**。
2. `_config.yml`、`package.json`、`pnpm-lock.yaml`、`CHANGELOG.md` 属共享文件：每次暂存前重读当前内容，确认对方改动已在 `main` 上落定或对方那部分确属本次要一起提交的，再动；hunk 切分在这个仓库被验证过无效，别试。
3. 版本三处同步（`_config.yml: version` / `package.json: version` / `CHANGELOG.md`）留到最后一步做。
4. 提交可以按本设计推进；**push 与部署单独征求同意**，且 push 前先 `git ls-remote` 核实远端状态。
5. `pnpm-lock.yaml` 必须与 `package.json` 同一次提交（CI 是 `--frozen-lockfile`，锁文件落后直接构建失败）。
