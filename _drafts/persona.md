### ⚠️ 关于 React / Vue 的口径（容易写错）

`[已核实]` 2026 年文章里 Vue 出现 16 次、React 出现 15 次，**两边都写**。
自己出货的项目（`account-password-helper`）是 **Vue 3 + wxt**；
但也在写 React 生态的东西（`2026-07-12-facebook-astryx.md` 讲 React 组件库 Astryx/StyleX）。

**正确写法**：「我自己出货的插件是 Vue 3 + wxt，但这篇讲的是 React 生态，所以对比时我尽量站在 React 使用者的角度。」
**错误写法**：「我是 React 开发者」或「我是 Vue 开发者」——两个都是片面的，而且读者一翻旧文就露馅。

### ⚠️ 关于包管理的口径

本仓库和自己项目用 pnpm，这是真的。但**不要写成「我只用 pnpm」**：
`[已核实]` `2026-07-12-alibaba-page-agent.md` 和 `2026-07-12-facebook-astryx.md` 的示例都写 `npm install`。

**正确写法**：引用第三方 README 时保留原文命令（`npm install xxx`），自己项目里写 `pnpm add xxx`，需要时加一句「我这边用 pnpm，你按自己的包管理器换」。
**禁止**：把上游 README 的 `npm install` 擅自改写成 `pnpm add` 然后声称是官方文档内容。

用它们等于给作者安一个新口癖，连续几篇就会显得刻意。

### 结构型口癖（比词更重要）

- **「不是 X，而是 Y」**：作者最爱的对比句式。`[已核实]` 「真正的痛点不是"存密码"，而是"快速找到并登录"」、「我做这个插件，不是因为市面上没有密码管理工具，而是因为…」
  - ⚠️ 这个句式和协议 §2.1-F「负向排比」高度重叠。**每篇最多 2 次**，且必须是真的在纠正一个常见误解，不能是空转的修辞。
- **「它们都能 X，但解决不了 Y」**：先承认对方能做什么，再指出缺口。比直接贬低可信。
- **列完要点后用加粗收一句**：`[已核实]` 「**以前是"先找账号，再登录系统"；现在是"打开系统，直接选账号"。**」
  - ⚠️ 加粗只包**具体结论**，禁止包形容词（协议 §2.2）。
- **直接对读者下指令**：「别急着往下看代码」「你可以试试它」

## 6. 情绪基线

**热情，但会算账。** 这是从语料里能提炼出的最稳定特征。

- 会真心夸：「恭喜你，新世界的大门打开了！」
- 但夸完立刻给条件：「别急着往下看代码，既然是"隐藏大招"，这玩意儿目前还是个实验性特性。如果你现在用的是普通稳定版的 Chrome，是跑不起来的。」
- 会主动说清"我为什么不用现成的"：整个 H2「我为什么不用 Chrome 自带，或者 1Password？」
- 不做无条件推荐：`[已核实]` 「不是它们不好，而是定位不同」

**推论（T2，可写但要标成判断）**：这个作者写推荐文时，读者的默认怀疑是"你是不是收了钱"，
所以他的应对方式是主动给出反面信息和适用边界。写新文章时沿用这个策略。

### ⚠️ 情绪的上限

即使是最好的样本，结尾也会失控：

- `[已核实]` 「这趟驶向"模型与网页直接对话"的列车，才刚刚鸣笛。」→ 违反 §2.1-K（空心展望）+ N（情绪回扣尾句）
- `[已核实]` 「**WebMCP，则是把我们这帮前端工程师拽上了下一代"AI 原生交互"的牌桌。**」→ 违反 §2.1-C（历史意义拔高）
- `[已核实]` 「将成为生死攸关的指标」→ 违反 §2.2 确定性滥用

**热情要留在中段的具体发现上，不要在结尾升调。** 结尾越平静越可信。

## 7. 可继承 vs 必须放弃

### ✅ 可以继承（这些是真实且有效的）

1. 技术判断的方向感：愿意下结论，不和稀泥
2. 先承认对方优点再指出缺口的对比结构
3. 具体的第一人称经验：「我以前也用过 Chrome 自带密码管理，也用过 Excel、飞书文档、备忘录」
4. 带编号的真实工作流（7 步日常用法那种）
5. `项目地址：` / `在线演示：` 结尾 + 求 star
6. 中文描述性图片 alt
7. 7 键 frontmatter 格式
8. 安全提醒用 `>` 引用块单独放结尾
9. 非可移植的 H2 命名：「痛苦回忆录：那些年被 DOM 支配的恐惧」「技术架构：给同行开发者一个交代」「我为什么不用 Chrome 自带，或者 1Password？」

### ❌ 必须放弃（详见协议 §2.6）

1. `## 总结与展望` 当 H2——三篇文章都用了，是最明显的批量生产痕迹
2. 五个必需维度写成五个同名 H2（`## 目前的局限性`、`## 实际场景思考：它能做什么？`）
3. 通不过可移植性测试的展望段
4. T3 虚构的组织/场景细节（`我们内部有个 CRM 系统，表单字段多达 30 多个`）
5. 结尾升调（列车鸣笛、牌桌、新纪元、先行者之一）
6. `当然，X 也有它的边界` 这类喉部清嗓
7. 万金油批评（`这些问题都在快速迭代中`、`项目团队非常活跃`）
